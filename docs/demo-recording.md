# Record a hold-to-talk demonstration

Record one real dictation into an empty coding-assistant prompt. Show the caption
and the destination field together. The goal is to show what holding and releasing
Super actually does, including the delay before insertion.

## Prepare

1. Use a new conversation with no private code or messages visible.
2. Close notifications that could appear over the recording.
3. Load the model before recording by holding Super once and waiting for ready.
4. Focus the empty prompt field.
5. Start your desktop screen recorder with microphone audio enabled.

Do not include other people's messages, voice, or personal information.
Keep the assistant name visible only if this is a real test of that client.

## Record

Aim for about 20 to 30 seconds. Keep one continuous shot from key-down through
insertion. Do not replace the recognized text with a prepared result.

| Step | Show |
|---|---|
| Before speaking | The empty prompt field. |
| Hold left Super | The real caption box opens. |
| Speak | Read the example below at your normal pace. |
| Release Super | The recognized text enters the prompt field. |
| Finish | Leave the inserted result visible. Do not submit the prompt. |

Example to speak:

> Please review this change for bugs. Focus on cancellation and error handling.
> Explain any problems before changing the code.

If recognition makes a mistake, either leave it visible or show the correction.
Do not describe a replay or simulated key event as a live keyboard demonstration.

## Publish

Review the full recording for private content before uploading it.
Use a caption that states the desktop and client actually shown.
Do not generalize one successful test to all AI clients.

Link the recording near the beginning of the README and from the voice-typing
guide. Keep the written steps available for readers who cannot play the video.
